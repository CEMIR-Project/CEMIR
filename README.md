## Data

`data/raw_episodes/` must be populated with the episode JSON files the pipeline operates on. `data/fiser_samples/sample_fiser_response.json` provides one-shot example responses used during evaluation and is included in this repository.

## Running the pipeline

Run the following scripts from the repository root, in order.

**1. Text enhancement**
```
python scripts/01_enhance_text.py
```
Reads `data/raw_episodes/`, writes `data/enhanced_text/`.

**2. Image generation**
```
python scripts/02_generate_images.py
```
Reads `data/enhanced_text/`, writes `data/images/`.

**3. Dataset assembly**
```
python scripts/03_restructure_dataset.py
```
Combines `data/raw_episodes/`, `data/enhanced_text/`, and `data/images/` into `data/dataset/`, with one folder per episode.

**4. Evaluation**

```
python scripts/04_run_local_qwen_eval.py
python scripts/04_run_local_qwen_eval.py config_qwen_baseline.yml
python scripts/05_run_gpt5_eval.py
```

The first command evaluates Qwen2.5-Omni-3B locally under `config_local_qwen.yml`, ablating which input modalities (raw text + enhanced text, raw text + image) are given to the model. The second evaluates Qwen2.5-Omni-3B under `config_qwen_baseline.yml`, using it as an additional model in the FISER-vs-CEMIR comparison. The third evaluates the GPT-5 model family via the OpenRouter API under `config_gpt5.yml`, for the same comparison. Each run writes per-episode JSON results under `results/<pipeline>/separate_results/<experiment>/<run>/`, where `<pipeline>` is `local_qwen_ablation` or `method_comparison` depending on the configuration used.

Both evaluation scripts skip episodes that have already been written, so an interrupted run can be restarted without repeating completed work.

**5. Aggregation**
```
python scripts/06_aggregate_results.py local_qwen_ablation
python scripts/06_aggregate_results.py method_comparison
```
Consolidates `results/<pipeline>/separate_results/` into `results/<pipeline>/agg_result/`.

**6. Analysis**

```
cd analysis/scripts
python 01_build_dataframe.py
python 02_ablation_summary_table.py
python 03_ablation_table4.py
python 04_method_comparison_tables123.py
python 05_aggregate_success_fig2.py
python 06_success_levels_fig3.py
python 07_model_specific_comp_fig4_5.py
```

`01_build_dataframe.py` reads both `results/local_qwen_ablation/agg_result/` and `results/method_comparison/agg_result/`, and writes `analysis/data/ablation_customized_new_Qwen.csv` and `analysis/data/final_whole_summary.csv`. Every other script reads only from these two CSVs — none of them read from `results/` directly — and writes its own output into `analysis/results/` (CSVs) or `analysis/figures/` (plots). Scripts `02`–`07` are independent of one another and can be run in any order. `analysis/results/` and `analysis/figures/` are regenerated by running the scripts and are not tracked in the repository.

## Provided results

`analysis/data/ablation_customized_new_Qwen.csv` and `analysis/data/final_whole_summary.csv` are the episode-level result tables produced by `01_build_dataframe.py`, and are included in this repository so that the analysis and figures can be reproduced directly without re-running model evaluation. Running `01_build_dataframe.py` again against a fresh `results/` directory will regenerate both CSVs in the same format at the same paths.

## Analysis details

This section describes the analysis scripts in `analysis/scripts/` in more detail.

### Ablation analysis (`analysis/data/ablation_customized_new_Qwen.csv`)

Ablates which input modalities are given to Qwen2.5-Omni-3B, holding the model and prompting method fixed. Contains episode-level, repetition-level results (`model`, `modality`, `level`, `episode_id`, `repetition`, `exact_acc`, …) for two modality conditions (raw text + enhanced text, raw text + image) plus a FISER baseline.

- **`02_ablation_summary_table.py`** computes the mean exact-accuracy and standard error for each modality at each difficulty level, and writes `analysis/results/ablation_summary_table.csv`.
- **`03_ablation_table4.py`** computes cluster-level paired permutation tests and bootstrap confidence intervals comparing each modality condition against the FISER baseline, and writes `analysis/results/table4_cluster.csv`.

### Method comparison analysis (`analysis/data/final_whole_summary.csv`)

Compares FISER and CEMIR prompting across a family of models (GPT-5, GPT-5-mini, GPT-5-nano, and Qwen2.5-Omni-3B), holding the modality set fixed per condition. Contains episode-level, repetition-level results (`model`, `level`, `episode_id`, `repetition`, `method`, `exact_acc`, …) for FISER and CEMIR across all four models and four ambiguity levels.

**Statistical method (tables).** Tables report the raw attempt-level success rate (SR%). Significance is assessed with cluster-aware inference:

- **Unit of analysis:** each *episode* (not each episode × repetition pair) is treated as an independent cluster. For every episode, the per-episode mean outcome (fraction of successful repetitions) is computed for each method.
- **p-value:** a cluster-level paired permutation test on the per-episode differences (episode sign-flip, two-sided).
- **95% CI:** a cluster bootstrap on the paired per-episode difference (resampling episodes, not raw rows).
- **Multiple comparisons:** Holm–Bonferroni correction applied within each table's family of tests.

This avoids treating the repetitions of the same episode as independent observations, while leaving the reported SR%/Δ values unchanged in meaning from the original attempt-level numbers.

**Figures.** Figures 2–5 show the same SR% values as the corresponding tables (computed with the same simple attempt-level mean), displayed as plain bar charts with no error bars or significance markers. Statistical significance is reported only in the tables (`analysis/results/table*_cluster.csv`, `p_holm` column).

- **`04_method_comparison_tables123.py`** writes:
  - `analysis/results/table1_cluster.csv` — aggregate SR% by model (all levels pooled)
  - `analysis/results/table2_cluster.csv` — aggregate SR% by difficulty level (all models pooled)
  - `analysis/results/table3_cluster.csv` — SR% by model × difficulty level
- **`05_aggregate_success_fig2.py`** produces the aggregate success rate comparison of FISER vs. CEMIR across the four models, saved to `analysis/figures/Fig2_Aggregate_Success_Rate_Updated.png`.
- **`06_success_levels_fig3.py`** produces the success rate comparison of FISER and CEMIR across the four difficulty levels, saved to `analysis/figures/Fig3_SR_by_Level_Updated.png`.
- **`07_model_specific_comp_fig4_5.py`** produces the per-model, per-level comparison charts, saved to `analysis/figures/Table3_Level{1,2,3,4}_Updated.png`.

### Image Fidelity Annotation Log

To evaluate the quality and consistency of the generated multimodal data, a manual review was conducted on a stratified sample of episodes. The results of this review are located at `analysis/annotator_agreement_log.csv`. This file logs the episode name, action step number, individual assessments from two independent reviewers, and the final resolved decision for 498 sampled action steps.

## Dataset Availability

The complete dataset used in this project is publicly available on Hugging Face: [HandMeThat V2 — CEMIR Subset](https://huggingface.co/datasets/CEMIR-Project/HandMeThat-V2-CEMIR). This dataset is a multimodal subset of the original [HandMeThat V2 dataset](https://github.com/Simon-Wan/HandMeThat), specifically prepared for the CEMIR project.
